## 1. Supported rule language

The translator is table-driven; every CSV row is executed, nothing is hard-coded
to a device name or to a particular document hash.  Implemented semantics:

- **Patterns**: `//`-segmented `yang_key` patterns with `$VAR$` placeholders,
  several placeholders per segment (`$ACL-SET$ $TYPE$`), literal keys (including
  keys containing spaces such as `SNMP-Filter ACL_CTRL`), implicit
  `$INTERFACE$`/`$NAME$` binding for `interfaces/interface/<name>`.
- **Precedence**: highest literal-character specificity wins; `[['NONE']]` rows
  suppress broader rows (this is what keeps `eth0`, `BMC`, `Vlan2`,
  `GigabitEthernet0` out of the `PORT` table and route `Bridge-Aggregation*` to
  `PORTCHANNEL`); ties are applied in CSV order.
- **Selectors** (`yang_value`): `unchanged`, enumerations (`true/false`,
  `permit/deny`, …), `any`, `NONE`, `default`, `compute`, `combination`,
  `string_combination`, `list_combination`, `list_value`, `list_2_string`,
  `empty_dict`, `lowercase`, `ockey` with branch lists / `ockey_default` /
  `ocvalue`, and the lone `ip` type token.
- **Values** (`sonic_value`): constants, variable templates, `+` concatenation,
  `[TABLE|KEY]` foreign-key references (emit the key), `{|ockey=path}` key
  suffixes, `NONE` (omit field), `empty_dict` ({}) and multi-value candidates
  (JSON lists).
- **Transforms**: `10000-original` (ACL priority), `original//1000`
  (port speed, hold-time), `log2(original)` (buffer `dynamic_th`, fractions such
  as `1/8 → -3`), `lowercase`, `list_2_string`.
- **Output**: `{ TABLE: { "KEY1|KEY2": { FIELD: value } } }` — SONiC config-db
  shape; two-segment sonic keys produce `{}` values; values are JSON strings
  unless the rule asks for a list.

## 3. Rule groups that cannot apply to this document (by design)

Two independent reasons; both are recorded rather than "fixed" by inventing
rules:

1. **The document does not contain the OC root the rules address.**  These rows
   are dead for any document of this shape: `DEVICE_METADATA//localhost` (21),
   `SYSTEM_PORT` (6), `BUFFER_POOL` (4), `BUFFER_PROFILE` (7), `BUFFER_QUEUE`
   (1), `BUFFER_PG` (1), `BGP_VRF` (4), `BGP_VRF_LEAKING_IPV4/6` (2),
   `PBR_RULE/PBR_NHG/PBR_NHG_MEMBER` (13), `LLDP_GLOBAL`, `NTP`, `SNMP`,
   `TACPLUS`, `SYSLOG_SERVER` (2), `TELEMETRY`, `telemetry-system//*` (10),
   `multicast//*` (15), `mqc-acl//*` (4), `vxlan//*` (2) — 75+ rows.
2. **The document has no such leaf** (valid root, absent subtree): e.g.
   `system//overlay` (51 rows), `system//hash//dlb|dhash` (26),
   `system//mirrors` (7), `fcr` (5), `mod` (3), `gnoi` (1), most `system//counter`
   sections, `system//aaa//config//fail-through`, `system//breakout`,
   `system//hash//global` fields not present, `lacp` `lag-type`/`min-links`,
   `interfaces//...//config//alias|index`, `Vlan` flooding control fields,

## 4. Known functional gaps in the supplied document

These are cases where the document has meaningful configuration that the rule
table does not cover.  They are **not** implemented, because inventing mappings
would be guesswork beyond the supplied manual:

- **Management VRF**: `network-instances/network-instance/mgt_vrf` is only used
  through the `ockey` lookup for `MGMT_INTERFACE.gwaddr`.  There is no
  `MGMT_VRF_CONFIG`, `VRF|mgt_vrf`, or `STATIC_ROUTES` entry: row 72 needs an
  `eth0/.../config/vrf` leaf that does not exist, row 438 needs
  `config/create-hw-vrf`, and row 493 hard-codes the `global` instance while the
  document's only static route lives in `mgt_vrf`.
- **`MGMT_PORT`**: row 73 needs `eth0/config/enabled-dci`; the document only has
  `config/enabled` (whose explicit rule is `NONE`), so no `MGMT_PORT` is emitted.
- **`ACL_TABLE|IFA_INGRESS|ports`** stays the literal `["PORTS"]`: the keyword
  appears once in the whole table (row 698/699) and is not bound by any OC path.
- **Interface metadata leaves** with no rule: `hold-time/config/down`,
  `ethernet/config/{aggregate-id,enable-flow-control,duplex-mode}`,
  `routed-vlan/config/virtual-mac-address` on Ethernet ports,
  `lldp/config/{enabled,management-address}`, `lacp/config/*`,
  `s-mlag-group`, `flow-interval`, `system/nd/interfaces/*`,
  `system/snmp/servers/*` (address/key/version/type), `system/clock`,
  `system/icmp`, `system/ssh-server`, `system/aaa/authentication/users`,
  `system/hash/{inner,outer}`.
- **`routing-policy//defined-sets//prefix-sets`** exists in the document but the
  rows 666/667 ockey chains need `config/sequence-id`, which the document's
  prefix entries do not have, so `BGP_IPPREFIXLIST` is not emitted.

## 5. Assumptions (explicit, where the manual is ambiguous)

1. **Specificity** is measured by literal characters, not by fully-literal
   segments — needed so `Bridge-Aggregation$INTERFACEID$` beats `$INTERFACE$`
   and `Vlan$INTERFACEID$` beats `$INTERFACE$` (otherwise 80 wrong `PORT` rows
   appear for port-channels).
2. **Multi-target `sonic_value` rows** carry one extra wrapper per target;
   single-target rows do not.  Candidates that are lists are emitted as JSON
   lists (`services: ["SNMP"]`).
3. **`list_combination` without `$VALUE_LIST$` accumulates** the substituted
   candidate of every matched leaf into a JSON list (`DNS|server|ip`,
   `SYSLOG_SERVER|...|servers`, `VLAN|Vlan2|members`, `BGP_PEER_RANGE|...|ip_range`).
4. **`string_combination` accumulates and comma-joins** (`PFC_WD_TABLE
   pri_enable`, `PORT_QOS_MAP pfc_enable`, `ACL_RULE ... IN_PORTS`).
5. **`[TABLE|KEY]` means a foreign-key reference** — the emitted value is the
   referenced key with placeholders substituted, not the bracketed text.
6. **Key segments are identifiers**: a field named `ip` (`DNS|server|ip`) is
   never value-substituted.
7. **`[['ip']]` on `interfaces/.../bmc/config/gateway-ip`** is a type marker, so
   `BMC|BMC|defgw` is the address itself.
8. **`log2(original)`** accepts fractions and is rounded to an integer
   (`1/8 → -3`, `8 → 3`).
9. **Later rule wins** when two rules write the same field (`SYSLOG_SERVER level`
   ends up `info`, not `notice`); identical re-writes do not duplicate output.
10. **Literal instance rules beat their `$NETWORK$` twins** for
    `network-instances/network-instance/global/...`; otherwise ~40 duplicated
    `...|global|...` keys would appear.
11. `ACL_RULE|<set>|DEFAULT_RULE` with `PRIORITY "1"` is emitted only when the
    document really contains entry id `1000` (it does for all three ACL sets);
    the entry-1000 leaves do not emit `RULE_1000` because the literal rules are
    more specific.
12. `ACL_TABLE|SNMP|ports` / `ACL_TABLE|SSH|ports` are `[""]` — that is what the
    supplier value list `[[['']]]` asks for; the set-level `ports` of
    `2000_IVLAN` is `["VLAN"]` (accumulated).
13. Table/key/field ordering follows rule order then document order; only the
    JSON content is semantically meaningful.

## 6. Cross-validation

Three rule groups were re-derived independently by hand from the CSV and the OC
document (files in `audit/`), then diffed against the translator's per-emission
provenance file with `tools/audit_diff.py --by-rule-rows`:

| audit | rule rows | expected lines | result |
| --- | --- | --- | --- |
| `audit/netinst.expected.txt` | 20 | 38 | 0 missing, 0 extra |
| `audit/system.expected.txt` | 78 | 738 | 0 missing, 0 extra |
| `audit/qos_acl_rp.expected.txt` | 69 | 885 | 0 missing, 0 extra |
| `audit/dsl.expected.txt` | 35 | 625 | 0 missing, 0 extra |

The remaining `interfaces` / `lacp` / `lldp` / `int` / `relay-agent` plumbing is
covered by `audit/dsl.expected.txt` (the hard-directive rows) and by the unit
tests (`tests/test_translator.py`).  The diffs found three real implementation
bugs that are now fixed: `log2(1/8)` fell back to 0 (buffer `dynamic_th`), field
names were value-substituted (`DNS|server|ip` became the address), and bare key
tokens were substituted as variables (`BMC|INTERFACE|...` became `BMC|BMC|...`).
